## 1. Decisions (one or two sentences each)

1. `compile_workflow(spec: PolicySpec, openapi: dict) -> tuple[dict, CompileReport]`. Tuple because the design returns a workflow and a report; the pipeline needs both.
2. Hooks stay import-free; the facts node (engine, runs as code) writes two extra helper strings, `business_days` (comma-joined ISO business days from today through the latest deadline of the handled products) and `callback_dates` (comma-joined allowed callback dates, `''` when the window has gaps). Reason: the platform only verified `json/re/datetime` for `code_exec`, never for hooks.
3. Final state routing: model-triggered `transition_to_finalize` is the normal end. `finalize` is a gated code node: it computes `final_outcome/final_reason` only when `closing_ready == 'yes'`, else it routes back to `negotiate` (negotiate has `on_enter_first_entry_only: true`, so the return is silent). Reason: a same-turn variable transition would hang up before the model speaks the mandated sentence and the actual recorded values. `finalize_forced` (sets `closing_ready`, computes regardless) is the target of negotiate's `max_turn_transition`; it exists to avoid a negotiate/finalize ping-pong.
4. Callback pre-hook, invalid date/time: the spec has no "offer a valid slot" flag, so the hook does NOT clamp. It blanks the date and time body fields (sent empty; the API rejects an unreadable value), sets `vars['callback_state']='invalid'` and counts `callback_invalid_count`. The post-hook then forces `result['data']['ok']=False` and writes `what_to_do_next` telling the model to re-ask (up to `third_party.reasks_when_outside` times), then to call the no-valid-time exit transition. Chosen because it guarantees no invalid callback is recorded without needing a spec flag that does not exist. Risk: the blank request still shows in the ledger call log (listed under "to verify").
5. Goodbye: exits triggered by the model (is_tool_call) end in a silent `end_call` node; the task_message tells the model to speak the exit sentence and the goodbye text (`closing.goodbye_before_close.text`) in the same message that calls the transition tool. Exits triggered by state (identity failed, backend failure, forced timeout) end in an `end_call` node whose `spoken_message` is the spec's sentence (`identity.on_failure.say`, `promise_rules.on_failure.say`) plus the goodbye text, because the model never gets a turn.
6. Where the spec has no value, the compiler never invents one: it omits that prompt block, appends a string to `report.gaps`, and, only if the missing piece makes a hook meaningless (for example no `floor` data), the hook leaves the request unchanged.
7. Multi-product (`spec.multi_product.enabled`): `N = max_products`, hooks loop `k = 1..N` over `p<k>_*`. A close action whose reason is in `multi_product.notes.reasons` and whose outcome is `no_promise`/`paid`-like (outcome in the notes-derived aggregation: `all_notes_equal.outcome` or `first_note_not_equal.outcome`) is NOT an exit path in multi mode; the prompt says "call the note tool with that reason for the current product". Transfers and non-note closes stay exit paths.
8. Queue -> reason map: derived by walking `intents[*].actions` (and nested `on_accept/on_decline/then`): a `transfer(queue=Q)` followed by `close(outcome, reason=R)` in the same list gives `Q -> R`. A queue with no mapping falls back to the queue name as reason and adds a gap.

## 4. Hook behaviour (what the tests assert)

All hooks read `field_map`-resolved body field names and the response key names from `cfg`. All wrapped in `try/except`. On exception: pre-hooks leave the body as the model sent it (except close, which writes the compile-time fallback), post-hooks leave `result` unchanged.

- `verify_post_hook`: `ok` false -> not counted, `what_to_do_next` = ask again in the right format. `ok` true and neither `verified` nor `all_verified`: if `hint` matches a spec hint with `counts_as_wrong` false -> not counted and `what_to_do_next` = hint instruction; else `identity_wrong += 1`. `identity_state`: `verified` when `all_verified` is `True`/`'true'`/`'True'` (or verified-count >= number of questions when the API gives no `all_verified`), `failed` when `identity_wrong >= max_wrong_total` or `wrong_answers_left` <= 0 (only when ok), else `pending`; never downgrades `verified`. Removes `result['header']`. Sets next-step text per state.
- `callback_pre_hook`: validates `date` / `time` against `vars['callback_dates']`, `hour_start`/`hour_end`/`inclusive`/`must_be_after_now` embedded from the spec, `vars['today']`, `vars['now_time']` (string compare, zero-padded `HH:MM`). Invalid or `callback_dates==''` with a defined window -> blank both fields (decision 4). If the window has gaps (`callback_dates` empty because of gaps) leave the request unchanged and record `vars['callback_guard']='skipped'`.
- `callback_post_hook`: ok and not rejected -> `callback_state='scheduled'`, `what_to_do_next` names the recorded date and time and the exit transition; rejected -> `ok` forced False, re-ask text, after the allowed re-asks `callback_state='no_valid_time'` and text pointing to the no-valid-time exit.
- `promise_pre_hook`: product choice (single: index 1; multi: keep the model's id when it equals some `p<k>_id`, else the first product with `p<k>_promise != 'recorded'` and `p<k>_note == ''`); date clamp: candidates = `business_days` entries `<= p<k>_deadline`; pick the first candidate `>= requested ISO date`, else the last candidate; invalid/past date -> first candidate; no candidates (deadline unknown) -> unchanged and `vars['promise_guard']='skipped'`. Amount clamp: parse float; `> full` -> full; `< floor` -> floor; unparsable -> full; floor unknown and amount below full -> full; rounded to the spec decimals. Writes `vars['promise_idx']`, `vars['promise_sent_date']`, `vars['promise_sent_amount']`, `vars['promise_changed']` (`yes`/`no`).
- `promise_post_hook`: ok -> `p<k>_promise='recorded'`, date/amount saved, `closing_ready='yes'` when every product is recorded or noted; `what_to_do_next` states the ACTUAL recorded amount and date, adds "these differ from what the customer asked" when changed, adds the spec success sentence when set, then either "call the create_promise tool for the next product" or "say the goodbye text and call transition_to_finalize". Not ok -> `p<k>_promise_fails += 1`; while `fails <= retries_on_failure` text = call again with the same values; after that: multi with `on_promise_failure.note_reason` -> `p<k>_promise='failed'` and text = call the note tool with that reason; otherwise `promise_state='write_failed'`.
- `note_pre_hook`: force product id (same rule as promise but pending = no promise and no note); reason must be in the openapi enum, else replaced by `on_promise_failure.note_reason` when set, else the first enum value in `multi_product.notes.reasons`; if `vars['notes_blocked']=='yes'` records `vars['note_blocked_hit']='yes'` (the node is already left after a transfer; this is a belt-and-braces flag).
- `note_post_hook`: ok -> `p<k>_note=<reason>`, `closing_ready` check as above, text = next product or finalize.
- `transfer_post_hook`: ok -> `transfer_state='done'`, `transfer_reason` from the embedded queue->reason map (`literal`, list of pairs), `closing_ready='yes'`, `notes_blocked='yes'` when `multi_product.on_transfer.add_no_notes`; text = tell the customer they are being connected, say goodbye, call `transition_to_finalize`.
- `close_pre_hook` and `finalize_source` share one block: if `final_outcome` is set use it; else build `states = [{"product_id","promise_recorded","note_reason"}...]` from `p<k>_*` for `k=1..N`, call the embedded `aggregate_outcome(states, agg_spec, vars.get('transfer_reason'))`; if the outcome is empty use the compile-time fallback (`identity_state != 'verified'` -> pre-verification fallback pair, else post-verification pair; computed in the compiler from the spec, see `_fallback_pair`). Drop the reason when the outcome appears in the spec's reason-less set (outcomes whose outcome_table rows all lack a reason). `close_pre_hook` writes `config['body'][outcome_field]` and `[reason_field]` (pops the reason key when empty); on exception writes the fallback pair. `finalize_source(force=False)` does nothing unless `closing_ready == 'yes'`; `force=True` sets it first.
