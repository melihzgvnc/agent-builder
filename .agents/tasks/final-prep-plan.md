## Design decisions
1. Ledger storage in the Worker: an in-memory Map cache with write-through to an optional KV binding named LEDGER_KV (reads fall back to KV when the Map misses). Rationale: a Worker isolate can be recycled so memory alone loses ledgers; Durable Objects give strong consistency but need a migration/paid-ish setup and more deploy steps; KV is eventually consistent (up to ~60 s cross-location read lag) but a single customer's ledger is written and read from one location in practice and Free plan covers it (write limit 1000/day). Documented in DEPLOY.md including the fallback (no KV binding = memory only, loud `storage` field in /v1/health).
2. Mock is data-driven: gen_mock.py derives tools, their paths, parameter names, enums and required lists from the contract; semantic roles (identity-check tool, account tool, promise, note, callback, transfer, close) are detected from contract shape and tool names via heuristics (lowercase substring on name/description, e.g. "verify", "account", "promise", "note", "callback", "transfer", "close") written into dist/config.json "roles". Unknown or unrecognised operations get a generic recorder behaviour (record call, return {ok:true}). Unknown contract format -> print `WARNING (loud)` to stderr, fall back to heuristics, still emit output, exit 0.
3. Mock config lives in dist/config.json and dist/data.json, imported by dist/worker.js via a build-free import (wrangler bundles JSON imports); mock/worker.js is the template copied to dist/worker.js by gen_mock.py so wrangler deploys from mock/dist/. Field names in worker.js are NEVER constants taken from a brief or the contract: worker.js reads `config.fields`/`config.roles`.
4. Server URL override applies to a deep copy of the loaded openapi doc: servers = [{"url": override}] (replacing servers[0].url), implemented in a pure function `apply_server_url(doc, url) -> doc` in builder/inputs.py (new) and called from stage_load_inputs. Missing servers and no override still fails only in tools_gen.build_tool (unchanged behaviour), with a clearer message that names --server-url / BUILDER_SERVER_URL.
5. Folder ingestion lives in a new module builder/folder_input.py (os.scandir only), returns a `FolderInputs` dataclass {briefs: list[Path], openapi_path|None, openapi_doc|None, customers_path|None, extras: list[Path], skipped: list[(Path, reason)], log: list[str]}. BriefA-style names are not hard-coded other than the single documented name `BRIEF.md` (case-insensitive) that sorts first. Other briefs sorted by lowercased name. Customers file recognised by content: JSON list of objects with string `id` plus `identity` dict and `products` list (public-test-set shape) or a simpler list of objects with `customer_id`/`id` + `identity`/`products`. YAML only if `yaml` is importable (it is not a dependency; do not add one) else logged and skipped. .pdf read as text only via `pdftotext` if on PATH else skipped; .docx via `docx` library only if importable.
6. Pipeline plumbing: run_build gains optional keyword args `server_url`, `folder_inputs`, `customers` (all default None) so existing tests keep working; BuildContext gets the matching fields. The positional `briefs` of build.py becomes nargs="*" and a single directory positional is treated as --folder; argparse error when no briefs and no folder.
7. Ledger sources: `LedgerSource` Protocol (ledger(customer_id) -> dict) in builder/online_runner.py; `OrganizerLedgerSource` is the existing HttpBank.ledger behaviour; `MockLedgerSource(server_url, team_header=None, opener=urllib)` reads `<origin>/v1/practice/ledger/<id>` (origin = scheme+host of the server URL with any path such as /v1 stripped before appending /v1/practice/... ) and `MockBank` (session + ledger) wraps it. Selected in stage_online_test when ctx.server_url is set and ctx.bank is None. Auth header name/value come from environment variables BUILDER_MOCK_AUTH_HEADER / BUILDER_MOCK_AUTH_VALUE (optional; value never logged).
8. Trace: console text is teed (builder/tee.py) into an in-run capture buffer/file and Trace._write_log (which rewrites trace.log at finish) appends it as a final `== CONSOLE ==` section, so trace.log is one file: structured sections plus console text. A `redact(text)` helper masks current values of FREYA_API_KEY, FREYA_BANK_TEAM_KEY, ANTHROPIC_API_KEY, BUILDER_MOCK_AUTH_VALUE (non-empty, len>=6) in the tee, in _write_log and in trace.jsonl events.
