## Invariants (user-reported constraints, restated verbatim in spirit; every item below must respect them)

1. **A build must ALWAYS end with a saved workflow artifact on disk: `<run_dir>/workflow.json`**, even if extraction fell back to the minimal spec, the spec is invalid, the compiler raises, a stage crashes or hangs, or the time budget is gone. ## Design decisions (made here; the implementer does not re-decide)

| # | Question | Decision and reason |
|---|---|---|
| D1 | How is `--spec` kept as a dev override while `DEFAULT_STAGES["extract_spec"]` is `builder.extract.stage_extract` (as requested)? | `DEFAULT_STAGES["extract_spec"] = stage_extract` literally. New function `stage_spec_file(ctx)` (the old reader). `run_build` builds the stage table as `{**DEFAULT_STAGES, **({"extract_spec": stage_spec_file} if spec_path else {}), **(stages or {})}` so explicit test overrides still win and `--spec` never constructs an LLM. `stage_extract_spec` stub and its `NotImplementedStage` raise are removed (the class stays, `stage_online_test` uses it). |
| D2 | Fallback spec cannot compile. What produces the workflow? | New `compiler.compile_fallback(sources, openapi) -> (workflow, CompileReport)`: one initial `conversation` node `converse` whose `task_message` is generic instructions plus every brief paragraph verbatim (taken from the loaded brief texts, no values in code), all openapi operations as `api_call` tools built with `tools_gen.build_tools` (model-filled bodies, `{{field}}` defaults like every other tool), the operation that has an `outcome` body property is a normal node tool (model-filled enum), one `is_tool_call` transition `transition_to_end_fallback` to an `end_call` node. `system_prompt` generic. Lint must give 0 errors. Reason: no hooks/engine are needed, nothing platform-unverified is added, and it is spec-independent so it also works when the spec is `None`. |
| D3 | When is the fallback workflow used? | In `stage_compile_workflow`: (a) `ctx.spec is None` (extraction crashed/skipped/timed out), (b) `ctx.results["spec_invalid"]` (validate stage set it, see D4), (c) `CompileError`/`SpecError`/any exception from `load_spec` or `compile_workflow`. Each logs `trace.error` or `trace.warn` with prefix `DEGRADED:` / `FALLBACK WORKFLOW:`; `compile_report.json` gets `"fallback_workflow": true` and the reason. (d) final safety net in `run_build` (D5). |
| D4 | Invalid spec behaviour must stay as the existing test expects. | `stage_validate_spec` on errors: unchanged behaviour (warnings, no `spec.json`, raises, exit 1) plus `ctx.results["spec_invalid"] = True`. The compile stage then takes the fallback path (D3b). `REQUIRES["compile_workflow"]` becomes `("openapi_doc",)` so a missing spec no longer skips compile. |
| D5 | Hard guarantee of `workflow.json`. | `ensure_workflow_on_disk(ctx_or_none, run_dir, briefs, openapi_path, trace)` called in `run_build` after the stage loop and inside its own try/except: if `run_dir/workflow.json` is missing, read the brief files directly (each read guarded), load openapi if possible, call `compile_fallback`; if even that fails write `compiler.emergency_workflow()` (static generic conversation node + end_call node, no tools). Logs `trace.error("workflow.json missing after all stages ...")`. Exit code is not changed to 0 by this; a degraded run keeps its failure code. |
| D6 | Exit code for a fallback extraction. | Unchanged contract: exit 0 iff no stage crashed. Degradation is signalled by `DEGRADED:` warnings in `trace.log` WARNINGS (and `ctx.results["degraded"]` list), not by the exit code, so `--dry` CLI tests without a key still exit 0. |
| D7 | Total time guard. | `run_build(..., budget_s: float = TOTAL_BUDGET_S)` with `TOTAL_BUDGET_S = 1500.0` (25 min, 5 min under the 30 min rule); `build.py --budget SECONDS`. `BuildContext` gets `deadline`, `extract_budget_s`. Extract budget = `clamp(min(480, remaining - 240), 30, 480)`; if `remaining < 60` extraction is skipped (D3a). Before each non-essential stage, if the deadline passed: log `skipped: total time budget exhausted` loudly. Essential (always run): load_inputs, validate_spec, compile_workflow, lint, offline_checks. |
| D8 | A stuck LLM/network call must not exceed the budget. | `run_stage(name, fn, ctx, timeout_s=None)`: when `timeout_s` is given, the stage runs in a daemon thread on a shadow copy of the context (`copy.copy(ctx)` with its own `results` dict); on time-out the stage is logged `failed` (`stage X exceeded N s, abandoned`), the shadow is discarded, so a late finish cannot corrupt state; on normal completion fields and `results` are merged back into `ctx`. Time-outs come from `STAGE_BUDGETS` (seconds): load_inputs 10, extract_spec 540 (480 + 60 grace), validate_spec 10, compile_workflow 60, lint 30, offline_checks 120, dry_run 120, save 120, read_back 60, export 60, smoke_test 180, online_test 600; effective timeout = `min(STAGE_BUDGETS[name], remaining)` but only applied to `extract_spec` and the network stages (CPU stages run inline). `run_build` accepts `stage_timeouts: dict[str,float] | None` to override (tests). |
| D9 | Where do offline self-checks live and when do they run? | New module `builder/selfcheck.py` (+ `builder/sandbox.py` with the restricted exec helpers copied from the test harnesses, so build code does not import from `tests/`). New stage `offline_checks` inserted in `STAGE_ORDER` right after `lint`, NOT in `NETWORK_STAGES`, `REQUIRES = ("workflow","spec")`. It never raises for failed checks (returns a summary string), writes the results into `compile_report.json` under `"selfcheck"`, logs `trace.error("selfcheck FAILED: ...")` per failed check and `trace.warn` for warnings. Skipped (`StageSkipped`) when the workflow is a fallback workflow. |
| D10 | How does the self-check learn compiler internals (field names, products prefix, close tool, N products)? | `CompileReport` gets a new attribute `context: dict` (default empty, NOT in `to_dict()`), filled by `_Build.finish()` with `fields`, `facts_io`, `has`, `n_products`, `close_name`, `resp`. No re-derivation. |
| D11 | Where do scenario dates/amounts come from (no brief values in builder)? | Derived from the spec only: `today` = first business day on/after a fixed neutral anchor that is not a brief value, found with `engine.make_calendar`; times from `third_party.callback_window` via `engine.parse_hhmm`; products synthesised from `account_fields`, `amounts.full_amount_field`, `amounts.floor_fields` (all distinct floor field names set), one product per band using the band midpoint for the days-late field; full=1000.0, floor=400.0 are neutral numbers. Expected values always come from calling `builder.engine` in-process on the same inputs (oracle), the compiled code under test is the embedded copy run through `builder.sandbox`. |
| D12 | What may the compiler repair deterministically? | Exactly two repairs, table-driven in `selfcheck.REPAIRS`: failing callback scenarios -> recompile with `third_party.callback_window` removed from a copy of the spec; failing note scenarios -> recompile with `multi_product.notes.for_products_without_promise` set to false. One repair pass only. The repaired result replaces the original only if lint has 0 errors AND the failed-check count strictly drops; otherwise keep the original and warn loudly. Everything else is report-only (warn loudly, never mutate). |
| D13 | Contamination script: how are banned tokens derived without noise? | Two tiers. **Strict (fail, exit 1):** ISO dates/datetimes; any backticked, double-quoted, table-cell or JSON-leaf value that contains `_` or a digit, or has >= 3 words; matched case-insensitively, identifier-bounded for single identifiers (`(?<![a-z0-9_])tok(?![a-z0-9_])`), substring for phrases. **Advisory (printed, never fails):** single plain words. **Auto-allowed vocabulary (derived, not hardcoded):** tool names from `tools/openapi.json` paths and every property name in `builder/spec_schema.json`. Remaining legitimate generic hits go in `scripts/contamination_allow.json` with a mandatory reason; a stale (unused) entry fails the test. Real brief phrases in prompts are reworded, not allowlisted. |
| D14 | Scan scope. | `builder/`, `build.py`, `scripts/` as asked. Excluded: `scripts/check_contamination.py` and `scripts/contamination_allow.json` (they must name tokens), and `scripts/spikes/` by default (frozen Phase 2a live-API diagnostics that deliberately use real bank enum values, never imported by `build.py`); `--include-spikes` scans them and the report lists their hits as a NOTE. Fixtures used for derivation: `tests/fixtures/spec_brief_a.json`, `spec_brief_ab.json` (leaf strings) plus both briefs. The concurrently written `*_variant_*` files are never read (partial-write flakiness). |
| D15 | Rehearsal run mode. | `scripts/rehearse.py` runs `python build.py <briefs...> --dry --budget 1500` as a subprocess with a hard 1800 s wall-clock kill, parses `trace.jsonl` stage events, prints a per-stage table (stage, status, seconds, budget, OK/OVER), fails (exit 1) if any stage is over its `pipeline.STAGE_BUDGETS` entry, total > 1500 s (25 min), `workflow.json` missing, or `compile_report.json` lint has errors. `--spec FILE` passes through (keyless rehearsal and tests). |
